## 结论与优先级

工程已经有大量有价值的测试，以及共享 Rust Core、平台适配层、Readium 原生边界；主要问题是
质量入口失效、旧文档重复声明过时架构、部分 UI 函数承担过多职责，以及测试覆盖分布不均。
重复率不是当前最严重的问题。先让质量结果可重复、让新增问题失败，再逐步减少已知债务。

- 桌面 TTS 清理捕获原 Navigator，修复引用清空后漏清理、引用替换后清理错实例的问题。
  停止后保留失效会话标识供状态机拒绝迟到事件，避免旧错误将 idle 覆盖为 error。
- 移动 TTS 在配置、音色查询、音色保存各异步阶段检查当前会话；取消后不再继续查询或写入
  音色偏好。新增合成成功/失败迟到的测试，覆盖取消、停止、结束、错误、重启和卸载。
- 完整回归发现桌面上传状态的两处问题：初始缓存查询可覆盖早到的上传事件，移除查询又可能
  让已挂载条目停留在“上传中”。进度改为订阅原生事件维护的缓存，失败/清理时更新缓存并通知
  订阅。测试明确验证初始加载期间的事件，以及书库级、单书级失败后的可见状态转换。
- 移动 TTS 设置测试在保存返回后再进行下一步交互，消除仅等待 API 被调用就继续操作的竞态。
  所有上述实际行为修复均有失败后转绿的回归证据；不以缓存内部 null/undefined 表示作为 UI 合同。
