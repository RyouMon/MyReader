# MyReader 设计工作区

`.superdesign/` 用来版本化保存设计探索、页面原型和迭代快照。这些文件是有价值的项目历史，可以直接在浏览器中评审，但不自动代表当前已经交付的产品行为。

## 各目录的职责

| 位置 | 职责 |
|---|---|
| [`docs/DESIGN.md`](../docs/DESIGN.md) | 已稳定的产品设计决策，以及设计系统的边界 |
| `.agents/skills/myreader-design-system/colors_and_type.css` | 可供工具读取的颜色 token 单一来源 |
| `my-reader/src/design-tokens.css` 与移动端 token 文件 | 已交付的平台实现 |
| `.superdesign/` | 探索稿、功能原型、备选方案与历史参考 |
| 产品源码 | 当前实际交付内容的最终依据 |

当前设计系统有意只管理跨端共享的语义颜色。设计稿提出了稳定、可复用的规则时，再把对应规则沉淀进设计系统；只服务于单个功能的布局、文案和交互探索继续保存在这里，不默认升级为全局规则。

## 管理流程

1. 在 `design_iterations/` 下创建聚焦的 HTML/CSS 原型，并使用能说明功能和版本的文件名。
2. 在浏览器中评审和迭代，不把原型直接当作已交付 UI。
3. 方向确认后，在对应的桌面端或移动端 package 中实现。
4. 如果确认稿改变了可复用的颜色规则，更新颜色 token 单一来源，并运行 `node scripts/sync-design-tokens.mjs`。
5. 把长期有效的系统级决策记录进 [`docs/DESIGN.md`](../docs/DESIGN.md)。过时稿可以保留作为上下文，或在本文件中明确标记，不应无说明地删除。

## 现有稿件

除非某份稿件被产品源码或设计决策记录明确引用，否则默认把它视为探索稿或历史参考。例如，`design_iterations/library_grid_1.html` 已被无封面渐变的产品实现引用。

提交新稿件前，应移除凭据、私人服务地址、个人文件路径，以及不能重新分发的版权内容。
