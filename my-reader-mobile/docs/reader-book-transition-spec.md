# Reader Book Transition Target

本文记录移动端打开/关闭图书转场的目标效果，作为后续 RN 原型或原生实现的对齐依据。

## 核心隐喻

转场不是“路由切换后盖一层封面动画”，而是一本实体书被拿起、翻开、合上、放回去。

动画对象分为两层：

1. 书籍内容层
   - 起始大小和位置与被点击的封面完全一致。
   - 打开时只做位移和缩放，从封面位置放大到阅读器区域。
   - 关闭时反向缩小，从阅读器区域回到原封面位置。
   - 关闭动画中必须使用真实 reader 内容，不要用假文本、黑底、占位页模拟。

2. 封面层
   - 起始大小和位置也与被点击的封面完全一致。
   - 打开时与内容层同步位移和缩放，同时做 3D 翻开。
   - 关闭时与内容层同步位移和缩放，同时反向合上。
   - 封面层始终在内容层上方，合上后最终盖住内容层，成为原位置的书籍封面。

全局背景约束：

- 打开和关闭动画中，内容层与封面层没有覆盖到的区域都应显示来源界面或返回后的首页/书库界面。
- 这些区域不能显示纯黑、纯白、reader route 背景、占位背景或任何整屏遮罩。
- 不应为了遮挡实现缺陷而给 overlay 根节点铺满不透明背景。

## 打开动画

期望流程：

1. 用户点击封面的瞬间，动画立即从该封面 frame 开始。
2. 同时生成内容层和封面层，两者初始 frame 都等于原封面 frame。
3. 内容层简单放大到阅读器区域。
4. 封面层一边同步放大，一边围绕书脊翻开。
5. 封面翻开的区域露出正在同步放大的内容层。
6. 封面未覆盖到的屏幕区域继续显示原来的首页/书库界面。
7. 内容层和封面层没有覆盖到的区域不能显示纯黑或 reader route 背景。
8. 动画结束时，阅读器内容自然接上，不应闪烁、先露出 reader、或显示黑底。

不要出现：

- 先跳到 reader，再播放封面动画。
- 封面之外的区域被黑色、白色或主题背景整屏覆盖。
- 内容层和封面层之外露出 reader route 背景。
- 用标题页、loading 文案或假内容替代书籍内容层。
- iOS 上由 modal presentation 造成下滑、漂移、闪烁。

## 关闭动画

期望流程：

1. 用户关闭图书后，不应先把 reader 路由移走。
2. 当前真实 reader 内容作为内容层，开始从阅读器区域缩回原封面 frame。
3. 封面层从翻开状态反向合上，并与内容层同步缩小。
4. 封面层在内容层上方，逐渐盖住内容层。
5. 内容层和封面层没有覆盖到的区域应显示返回后的原首页/书库界面，不能显示纯黑或 reader route 背景。
6. 动画结束后，封面正好落回原卡片位置，然后再完成真正的导航返回。

不要出现：

- 先 `router.back()`，再单独播放封面动画。
- 真实 reader 内容不缩小，只让封面缩小。
- 缩小区域外露出黑底、reader 路由底色、或任意假背景。
- 为了透出背景而改坏 iOS 打开动画的 native-stack presentation。

## 实现判断

当前 RN overlay 原型能较好表达打开动画，但关闭动画存在结构性限制：

- 打开时，来源界面本来就在底下，透明 overlay 可以自然透出。
- 关闭时，当前路由是 reader，来源界面在 native stack 后面，不一定能被 RN 透明看到。
- 强行使用 `transparentModal` 可能破坏 iOS 打开动画。
- Readium/PDF/WebView/native reader surface 也会让 RN 层截图、缩放、zIndex 更不稳定。

因此，如果继续追求完整目标效果，优先考虑原生层方案：

- iOS 使用 native custom transition / snapshot view。
- Android 使用 native shared element / custom transition / snapshot view。
- Expo native module 可以作为最小落地方式，负责创建 window 级转场层、截图来源界面和 reader 内容、播放 open/close 动画，再通知 JS 导航。

RN 方案如果继续保留，应只作为原型，不应为了关闭动画透背景而破坏已经稳定的 iOS 打开动画。
