# 用会话导航历史承接阅读跳转与远端位置

## 问题

显式跳转缺少多级撤销，用户容易丢失原来的阅读位置。多设备离线阅读产生并发位置时，
ADR-0016 的手动选择机制又让后续阅读停留在设备草稿，选择之前无法正常同步。
根本需求是能找回位置，同时继续阅读、保存和同步。

## 决策

- Core 继续保存完整 Readium Locator。因果后继自然覆盖已见值；真并发时按阅读记录时间
  `recorded_at` 选择续读投影，相同时间使用 operation ID 确定顺序。同步到达时间和书中进度大小
  都不决定赢家。
- 普通阅读保存始终写入同步文档。已有 `reading_position_drafts` 仍可读取；下一次阅读保存与
  清除遗留草稿在同一事务提交。保留旧迁移及旧调用兼容，不再产生新草稿。
- 当前打开的书拥有一份内存导航栈。显式跳转新增项，普通翻页、滚动、TTS 自然跟随只更新当前项。
  后退和前进沿导航顺序移动；后退后新跳转截断前进路径。
- 接收远端位置时不跳页，将其插入当前项之后，保留已有前进项。重复 operation ID 不重复加入。
  同步结果携带收到的完整位置，使本机随后自动保存也不会丢失该入口。
- 导航栈仅在本次打开的书内有效。后台、锁屏、重排不清空；真正关书后清空。
  `reading_progress` 负责跨关书、跨重启续读，无需额外永久历史或每设备历史表。
- 收到远端位置后临时显示其跳转按钮，用户翻页后隐藏。其他情况只在 Chrome 激活时显示；
  再次激活 Chrome 会恢复可用按钮。左侧返回、右侧前进，由导航栈顺序决定，与 Locator、百分比
  和书籍排版方向无关。

## 边界

Automerge 可以保留并发值，但产品不再有阻塞阅读或同步的“待解决冲突”状态。
数据库的续读投影与当前视口独立；接收同步不会自动移动正在阅读的页面。
导航历史由共享 TypeScript 状态机维护，平台仅连接现有导航入口、原生位置回调和 Chrome。
