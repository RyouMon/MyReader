# MyReader Agent Notes

## Repo Shape
- The runnable app lives in `my-reader/`. The repo root is not a Node workspace and does not contain the app's install/build scripts.
- Use `my-reader/package.json`, `my-reader/package-lock.json`, `my-reader/vite.config.ts`, and `my-reader/src-tauri/tauri.conf.json` as the source of truth, not the root `README.md` quickstart commands.

## Commands
- Install deps in `my-reader/`: `npm install`
- Frontend dev server in `my-reader/`: `npm run dev`
- Tauri dev app in `my-reader/`: `npm run tauri dev`
- Frontend production build in `my-reader/`: `npm run build`
- Tauri production build in `my-reader/`: `npm run tauri build`
- There are currently no repo-defined `lint`, `test`, or `typecheck` scripts. `npm run build` is the main verification step because it runs `tsc && vite build`.

## Architecture
- Frontend entrypoint: `my-reader/src/main.tsx`
- Routing is TanStack Router file-based routing from `my-reader/src/routes/**`.
- `my-reader/src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin. Do not hand-edit it.
- Tauri backend entrypoint: `my-reader/src-tauri/src/main.rs` -> `my_reader_lib::run()` in `my-reader/src-tauri/src/lib.rs`.
- Main desktop capabilities currently exposed from Rust are Calibre library management, paginated book queries, book detail lookup, and reading progress persistence via Tauri commands in `my-reader/src-tauri/src/commands.rs`.

## Data And Runtime Quirks
- The app expects Calibre library roots, not arbitrary folders. Adding a library validates that the selected directory contains `metadata.db`.
- App settings (Calibre libraries, active library, reader UI prefs) are persisted as `config.json` in Tauri's `app_data_dir()`.
- Reading progress is stored in SQLite at `my-reader.db` under the same `app_data_dir()`, in table `reading_progress`. **Target architecture** (not implemented yet): progress and notes live under each library root in `.myreader/` so they sync with the library tree; `app_data_dir()` keeps **per-machine** settings and library registration only. See design doc under `~/.gstack/projects/myreader/`.
- Book covers and book files are served through custom Tauri URI schemes registered in `my-reader/src-tauri/src/lib.rs`: `bookcover://` and `bookfile://`.
- The `tauri-plugin-mcp-bridge` plugin is enabled only in debug builds.

## Frontend Conventions
- Use the `@/*` import alias for `my-reader/src/*`.
- shadcn is configured in `my-reader/components.json` with `new-york` style, `neutral` base color, and CSS variables in `src/index.css`.
- `my-reader/biome.json` excludes generated/router output and `src/components/ui/**/*`; avoid mass-formatting generated files or vendored UI primitives.

## Editing Guardrails
- If you add or rename routes under `my-reader/src/routes/`, expect `my-reader/src/routeTree.gen.ts` to regenerate from the Vite plugin.
- `my-reader/src/lib/foliate-js/` is a vendored subtree with its own `package.json`; avoid incidental edits there unless the task is specifically about the reading engine/vendor code.
